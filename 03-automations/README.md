# Automations

Four skills. Each is a folder with a `SKILL.md`. If your tool supports installable skills,
point it here. If not, they work as plain instructions you paste in.

| Skill | Trigger | What it does |
|---|---|---|
| **resume-tailor** | a JD, a link, or `/resume` | Strategic read → tailored resume → hands off to the evaluator |
| **resume-evaluator** | after any resume, or "will this pass?" | Four reviewer passes + an honesty audit before anything is sent |
| **recap** | "update the OS", end of session | Routes what changed into the right file, logs it, shows you a diff |
| **job-scout** | "scout", "anything new posted" | Finds roles, applies hard gates, scores, drafts the best |

## The one that matters most
`resume-evaluator`. Writing a resume is the easy half. Knowing whether it survives an ATS
parse, an AI first-pass screen, a six-second recruiter scan, and a hiring manager who
manages this role — before you send it — is the half most people skip.

## Writing your own
A skill is a markdown file with a name, a trigger, and numbered steps. The ones here earn
their keep because they encode judgment, not formatting: when to skip a role, which number
is defensible, what never to repeat.
